# 开发者日志 01：把“守 · 望”做成可玩的十六分钟守夜

- 日期：2026-11-22
- 作者：xingwangzhe
- 阶段：核心循环、文化叙事与数据驱动原型

## 起点

项目在本届开发期内从空目录初始化。没有沿用已基本完成的旧项目，而是先阅读赛事主题与永昌堡、汤和信俗资料，再确定一个能连续体验的核心循环：玩家在十六分钟内移动、攻击、拾取经验、升级三选一，并在灯火风险与守夜阵位之间做取舍。

## 关键实现

- 用 `RunGame` 协调单局，`Battlefield` 负责战斗模拟与绘制，`MapLayout` 负责地图碰撞、流场和连通性。
- 将敌人、波次、兵器、被动、升级、地图和剧情放入 `game/data/*.json`，避免把内容写死在战斗脚本里。
- 采用 60Hz 固定步长；小怪使用数据数组与 `MultiMeshInstance2D`，弹幕和经验袋使用对象池，空间哈希单元为 64px。
- 叙事边界固定为：1386 年汤和序章；1559 年正篇唯一可操作人物是虚构守灯乡勇王陆。六张选择卡表示王陆的守夜阵位，不是六名独立人物。
- 文化卡同时保存中英文说明、类别与 `source_ref`。没有史料出处的句子标为“演绎”，不冒充史实。

## 遇到的取舍

早期方案更接近传统守城，但与“割草生存 + 升级三选一”的体验不够聚焦。最终保留塔、桥、水门和堡墙作为战场结构，把核心节奏收敛到持续移动、自动攻击和短周期Build选择。历史元素通过地形、阵位、兵器、图鉴和卡牌文化说明进入玩法，而不是只做背景文字。

## 结果

当前工程已具备完整单局结构、三张地图、六种阵位、七种兵器、十二种被动、Boss 与结算解锁。设计稿只在本地保留；公开工程入口见 [game/README.md](../game/README.md)。
