# 460 敌人压力测试 · 2026-11-23

## 目标

验证 1280×720 下 460 个敌人的渲染与更新路径，再决定是否写 C++ GDExtension。

## 结果

- 优化前：460 敌人，**930 draw calls**，每名敌人“影子 + 贴图”各一次绘制。
- 优化后：同场景 **14 draw calls**。
- 做法：按敌人贴图分批，使用 `MultiMesh` 批量绘制影子与本体；每批固定容量 512，
  不再逐敌人调用 `draw_texture_rect`。
- 视觉验证：本地现场生成压力场景截图核对（临时产物不入库）。

## 2026-11-24 复测：血条合并为单批 MultiMesh

桌面恢复正常后重新实采，发现上一轮遗漏的热点：**每个非玩家单位的血条
仍用 3 次 `draw_rect()` 绘制**，460 敌时合计约 939 次额外绘制。

- 改法：血条底色、按比例填色与四边细线全部写入同一个 `MultiMesh`
  （容量 3000，`use_colors`，白色 1×1 纹理），`_draw_health_bars()` 末尾只调用
  一次 `draw_multimesh()`；没有删除任何单位的血条。
- 实测（Intel Iris Xe / Mesa 26.0.8 / OpenGL 4.6 / 1280×720）：

  | 场景 | draw calls | 稳定墙钟 FPS | `update_world()` |
  |---|---|---|---|
  | 460 敌完整场景 | **23–24** | **59–60** | 5.3–7.1 ms |
  | 460 敌、关闭敌兵本体绘制 | 19–20 | 59–60 | 6.7–7.7 ms |
  | 460 敌、关闭世界更新 | 12 | 55–60 | — |
  | 空场景基线 | 4–5 | 60 | — |

- 结论：血条批次化后，敌兵本体与血条都不再是绘制瓶颈；桌面端稳定 60 FPS，
  无需引入 C++ GDExtension。

## 绝对 FPS 的环境限制

当前桌面会话里，**空场景**也只有约 1 实际帧/秒；Godot 把单帧 delta 截到约 0.133s，
所以日志里的 `fps=8.3` 不是有效 GPU 帧率。`gda perf monitors --frames` 在空场景与
压力场景都会 30 秒超时。因此本轮只接受可复现的 **draw calls 14 / 460 敌人** 与
无头 16 分钟平衡结果，不把本机绝对 FPS 当作验收。

绝对 FPS 必须在显示器正常唤醒的原生 Linux 桌面与 `windows-latest` / Windows
实机上复测。若那里仍低于目标，再按 AGENTS 写 C++ 宽相位查询；当前先不引入
GDExtension 构建复杂度。

## 复测入口

```bash
# 460 敌人压力场景，窗口运行
"$GDA_GODOT" --path game --scene res://tests/perf/stress_scene.tscn \
  --windowed --resolution 1280x720 --rendering-method gl_compatibility

# 空场景基线
"$GDA_GODOT" --path game --scene res://tests/perf/empty_scene.tscn \
  --windowed --resolution 1280x720 --rendering-method gl_compatibility
```

环境变量：

- `WATCH_STRESS_COUNT=460`：敌人数。
- `WATCH_STRESS_DRAW_ENEMIES=0`：关闭敌人绘制，隔离逻辑耗时。
- `WATCH_STRESS_SKIP_UPDATE=1`：关闭世界更新，隔离绘制耗时。
- `WATCH_STRESS_LOG=/tmp/stress.txt`：把 2 秒采样写入文件并立即 flush。
