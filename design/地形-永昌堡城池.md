### 3.1 变体纪律（核心约束）

**绝不允许跨语义随机取块。** 变体号由 `(col, row)` 的算术式 + 每类固定盐值得出：

```gdscript
# tile_catalog.gd
static func variant_index(category, c, r) -> int:
    return posmod(c * 7 + r * 3 + salt[category], variant_count[category])
```

- 同一格永远得到同一张图 → 布局**完全确定性**、可复现、可截图比对。
- 同一语义内相邻格错开（×7 / ×3 步长与 13、14 互质）→ 不出现条带或棋盘格。
- 不同语义盐值不同 → 不同材质的图案不会意外对齐。
- 4 层 TileMapLayer 全部在一次 `build()` 内写满，运行期零 `set_cell`。
- `TileCatalog.shared_tileset()` 用 `static var` 缓存，跨场景复用同一个 TileSet。

## 6. 三条驿道（lane）

三条驿道分别从北、东、南三门入城，终点均为城中心偏西的主堡（王氏宗祠）。
敌兵登陆点在堡东沙滩（对应「倭寇自海上来袭」）。

### 6.1 控制点（瓦片坐标；世界坐标 = 值 × 32）

| lane | 门 | 世界 Y | 控制点（格） |
|---|---|---|---|
| **0** 北路 | 通市楼（北） | 160 | `(96,4) → (33,5) → (33,31) → (26,31) → (26,36)` |
| **1** 东路（**主路**，带瓮城） | 环海楼（东） | 1504 | `(96,46) → (61,47) → (61,57) → (55,57) → (55,47) → (27,47) → (27,44)` |
| **2** 南路 | 迎川楼（南） | 2720 | `(96,84) → (33,85) → (33,61) → (24,61) → (24,44) → (26,44)` |

首点 `spawn_world(lane)` 由 `SPAWN_COL=96` + `LANE_ROWS[lane]` 派生，末点落在主堡门前（不侵入主堡格）。

**lane 1 的路径语义**（最能体现永昌堡形制）：沿海滩北上 → 折西横穿城外滩涂 → 折南贴瓮城东侧 →
折西从瓮城南门（`BARB_GATE_S`，cols 54-55 row 52）进入瓮城 → 北穿瓮城庭院 →

## 8. `blocked` 禁建规约

`build()` 产出的 `blocked: Dictionary`（键 `Vector2i(c,r)` → `true`）**必然包含**：

| 类别 | 生成来源 | 格数占比 |
|---|---|---|
| 城墙 / 瓮城墙 / 敌台 / 铺舍 / 建筑地基 | 结构层（`st[i] >= 0`） | 大 |
| 护城河 / 上河 / 下河 / 河浃 / 海 / 盐田引水沟 | 水掩码（`wmask[i] == 1`） | 大 |
| 驿道 / 街巷 / 桥 | 道路层（`rd[i] >= 0`） | 中 |
| 地图边界（2 格内缩） | `c < 2 or c > COLS-3 or r < 2 or r > ROWS-3` | 边 |

**「可走不可建」**：道路格虽然 `blocked=true`（建造系统会拒绝），但单位 Path2D 沿其行进。
这是刻意的双语义 —— `blocked` 只对建造系统生效，不是碰撞层。

总计 5771 个禁建格。城内可建 1268 格（够放约 140 座 3×3 建筑）。

### 10.1 性能

- `build()` 单次耗时 **~180-220ms**（headless，含 9 张图集贴图合成 + 10800 × 4 层 `set_cell`）。
- 4 层 `TileMapLayer`，一次构建，运行期零 `set_cell`。
- `TileCatalog` 用 `static var` 缓存 TileSet，重复进入战斗场景不再重建图集。
- 水体掩码 / 区域码用 `PackedByteArray`（10800 字节），`zone_map` 用 `Dictionary`（约 10800 项，仅 MinimapPanel 消费）。

### 10.2 确定性

布局计算全程**无随机数**：山脊/海岸用正弦曲线，变体号用算术式，装饰用固定散列 `(c*13 + r*29 + GEN_SEED) % 41`。
`GEN_SEED = 20260322` 仅作散列盐，不驱动 `RandomNumberGenerator`。
同一份代码在任何机器、任何帧率下产出**逐像素相同**的地图。

## 12. 遗留风险

1. **比例游戏化**：护城河 3 格（≈35m）宽于史载 3-5m，上河 2 格（≈23m）宽于史载 8-15m。
   这是为给塔位和单位行进留空间。若追求严格等比，需把 TILE 缩到 8px 或放大城内格数，会牺牲可玩性。
   当前取舍已在 §2 表中标注。
2. **城堞 908 个未逐个还原**：装饰层每 2 格一堞，约 100 处视觉示意。若需精确个数，需改为
   程序化沿墙生成并按周长均分，会显著增加装饰层瓦片数。
3. **上仓浃「穿墙而过」**：史载该浃穿过城墙给城外农田供水。当前实现为城内 (32,22) 5×1，
   未穿墙（穿墙会在城墙开洞，影响防御语义）。如需还原，须同步加一座城墙水洞。
4. **民居 26 座只还原 11 座**：其余以草地/水田填充，避免城内建筑过密挤压建造空间。
5. **南方巷道与真实街巷名未全对应**：新城街、御史巷、都堂巷有据；上仓街、仓前街为方位命名，
   史无确名，取「上仓浃」与「仓前」意会，已在代码注释标 `方位命名`。
6. **`zone_map` 是本轮与 UI 负责人协同产物**：若后续 MinimapPanel 需要新语义，请在
   `_build_zone_map()` 扩展，不要在我方 `zone_at()` 里做归并（会丢信息）。
